# 医疗分诊 JEV 模型训练与多方法评测

## 目标

以医疗分诊为完整应用场景，完成数据转换、医疗分诊 JEV 模型训练，以及自训模型、普通 Chat、现有 JEV 模型、LLM2Jev 等方法的统一评测。交付一个可保存、重新加载和推理的医疗分诊 JEV 模型，并用真实实验报告比较决策质量、概率校准、延迟、吞吐和成本。

主任务为 `triage_urgency`（四类分诊行动 Choice）和 `message_urgency_pair`（患者消息优先级 Choice），对齐 [jev-healthcare-lab](https://github.com/JuneYaooo/jev-healthcare-lab)。ESI 五级分诊保留为辅助 Score。三种业务监督可混合训练同一模型，评测按任务分别报告。

以下为待实现的 issue 需求；数据数量是固定来源核验后的建议示例划分，不代表模型已经完成训练或取得相应成绩。

## 数据使用与隔离要求

- 保留原题、原选项键、原标签和来源定位，不用模型重新标注测试题。
- CARE 仅使用当前已披露患者文本，排除医生参考回复、未来轮次、信息充分性和构造标签。
- 同病例、同消息及同病历不得因派生多个样本而跨训练、验证、校准和测试划分。
- 消息训练来自无 EHR 的 PMR-Reddit，主测试来自含 EHR 的 PMR-Synth；明确记录该来源与输入差异，不编造训练病历。
- CARE 与 PMR 发布数据声明 CC BY-NC 4.0，用于非商业研究；ESI 源仓库未声明独立数据许可，作者主张 Handbook fair use，使用与分发前需确认原手册及作者条款。

## 需要实现的内容

### 1. 数据转换

- 获取并固定上述来源的版本，记录 URL、revision、文件 SHA-256、原始划分和数据使用条件。
- 将训练、验证、校准样本转换为项目的 `decisionforge.training.v3`；将固定测试题转换为 `decisionforge.eval.v1`。模型可见的 `request` 与参考监督分离，原始病例、前缀、消息和来源组可追溯。
- 已有明确标签使用确定性转换：CARE 保留四类行动标签；PMR 根据源紧急程度构造配对标签；ESI 固定 rubric 并使用 `Score = 5 − ESI`。硬标签编码为一热监督，不能把编码中的概率 1 宣称为临床确定性。
- 先按病例／消息／病历分组划分，再构造派生样本。记录去重、测试关联组排除、歧义标签和实际各划分数量，不按派生题随机切分。
- 合并三个来源时重新分配唯一 record/group ID，保留来源映射。首版让两个主 Choice 任务在每个划分中数量相近，ESI 作为辅助监督；不复制少量病例来制造额外独立样本。
- 主 benchmark 的 100／30 题保留原始题面、病历、选项键与 gold；辅助 ESI 保留 216 条并标记一条无法唯一评分的参考。转换校验失败的记录应有明确原因，不能静默丢弃。

预期产物：原始来源清单、划分／去重审计、训练 v3 数据、固定评测 v1 数据，以及各任务和各角色的数量统计。

### 2. 模型训练

- 复用项目已有原生决策模型训练能力，首版以 `Qwen/Qwen3.5-4B` 为候选底座，固定权重 revision，训练医疗分诊 LoRA 与决策头。若部署或对照后端不支持该底座，在实验开始前统一选择可兼容底座并记录原因。
- 支持同一模型混合学习两项主 Choice 与辅助 Score；保留各自题型、候选集合、rubric 和完整监督分布，不把四类行动与五级 ESI 合并为同一标签体系。
- 明确训练 seed、采样比例、训练轮次／步数、batch、学习率、LoRA 参数、精度及最大输入长度。原始患者条件不能因截断而静默丢失。
- 仅 train 用于模型权重训练；validation 用于模型／超参数选择；calibration 用于概率校准。测试题不得用于训练、调参、prompt 选择或拟合温度。
- 先运行短训确认数据、训练、校准、保存及重载链路，再完成正式训练。最终保存底座身份、adapter／决策头、校准配置、checkpoint 和训练日志。
- 保存后重新加载模型，验证 Choice 选项键、Score 等级方向、rubric 与概率输出一致。训练和校准诊断按题型／任务记录，区分拟合诊断与独立测试结果。

预期产物：医疗分诊 JEV 模型、可恢复训练状态、实际训练配置与数据签名、训练／验证／校准报告，以及保存模型的重载验证记录。

### 3. 各类方法统一测评

至少覆盖以下四类方法：

| 方法 | 是否使用医疗训练数据更新权重 | 执行方式 | 对照目的 |
| --- | --- | --- | --- |
| 我们训练的医疗分诊 JEV 模型 | 是 | 重新加载本 issue 训练的原生决策模型，执行 Choice／Score | 衡量领域训练后的决策质量和运行表现 |
| 普通 Chat baseline | 否 | 同一底座原始权重，通过固定 zero-shot Chat prompt 输出选项键或等级 | 提供普通生成式调用基线 |
| 现有 JEV model | 不进行本 issue 的医疗微调 | 调用已有 JEV 服务／checkpoint，固定版本并记录实际返回的模型身份 | 对照现成原生 JEV 系统 |
| LLM2Jev baseline | 否 | 同一底座原始权重通过 LLM2Jev 决策接口输出标签／概率 | 区分无需训练的推理适配与医疗参数训练 |

LLM2Jev 首选项目既有对照路线采用的 [Yinsongxu/LLM2Jev](https://github.com/Yinsongxu/LLM2Jev)：使用已有模型权重、通过候选 yes/no logits 形成决策概率，无需医疗微调。固定其 commit、服务后端、prompt、精度和打分参数。另一个同名项目 [tic-top/llm2jev](https://github.com/tic-top/llm2jev) 采用选项标签 token 的打分方式，如纳入，应作为独立方法行，不能混记成同一个 LLM2Jev 实现。

如需进一步区分“领域微调收益”和“决策接口收益”，可追加同底座、同医疗训练数据的 Chat-SFT 对照；若额外微调 LLM2Jev，也必须单列训练版本，不混入无需训练基线。

#### 统一输入与方法适配

- 为自训模型、Chat、JEV、LLM2Jev 提供统一评测入口，复用固定数据、指标、逐题记录、恢复和离线重评分能力。优先复用项目已具备的 adapter，补齐尚不支持的接入和能力声明。
- 每种方法接收相同的公开病例事实、问题、选项和 rubric，禁止发送 gold、来源构造标签、未来轮次及评分信息。Chat 可使用固定序列化模板，必须校验事实和候选完整保留。
- Chat 与无需训练 LLM2Jev 使用相同底座权重；自训模型由该底座初始化。固定并记录权重 revision、模型规模、精度、量化、上下文长度、thinking 设置和服务引擎。现有 JEV 的未知底座／硬件条件明确披露，不能视为同底座消融。
- 主结果按模型实际返回的原选项键计分，不用概率 argmax 代替返回 Choice，不把 `Patient #1` 改成 `Patient_1`。拒答、缺失、非法选项、未完成响应和超时均保留，并在固定题数分母中按错处理。
- 概率指标另行校验和报告。区分原生决策头概率、LLM2Jev logits 派生概率、Chat 自报概率；没有合法完整分布的方法不计算概率指标，不能用一热补值、均匀分布或额外 judge 调用伪造概率。
- 两项主 Choice 任务要求四类方法均完成。辅助 Score 若某个服务不支持，应明确标记 unsupported，不通过改题型或换模型伪装为相同方法的结果。

#### 质量指标

| 任务 | 必需指标 | 分母与说明 |
| --- | --- | --- |
| 分诊行动 | Accuracy、Macro-F1、逐类支持数／召回、混淆矩阵、来源组全部答对比例 | 固定 100 题；Macro-F1 平均金标中出现的行动类别；补充紧急就医类漏判统计 |
| 消息优先级 | Accuracy、合法输出率、失败／缺失统计 | 固定 30 对；患者 1／2 是位置选项，不当作临床类别计算 Macro-F1 |
| 辅助 ESI | 等级 Accuracy、等级误差、混淆矩阵、低估／高估分诊及严重低估 | 216 条中 215 条有唯一参考；一条歧义参考单列排除；说明有效预测、失败与未尝试的分母 |
| 有合法完整概率的结果 | Brier、ECE；Score 的概率期望 MAE | 标明概率来源、校准方式和有效覆盖，不与仅输出离散等级的方法混称同一概率口径 |

每个任务分别报告各方法的成绩、样本数、失败数和覆盖率，不用跨任务“医疗总分”掩盖差异。30 对消息的结果作小样本解释；同病例的多个前缀、复用的 ESI 病例和重复负载不能当作额外独立患者。需要误差范围时按来源组统计。

#### 延迟、吞吐和成本

- 质量先用同一份全量固定题集完成单题协议对照；记录端到端延迟 P50／P95、合法判断吞吐、token 用量、调用失败与重试。
- 若复现参考仓库的多题负载，另设明确的每请求题数、并发 8／32、预热和计时窗口；只比较实际支持该协议的方法。多题与单题成绩／速度分开，不将不同协议混在同一性能结论中。
- 记录 GPU 型号、显存、batch、实际在途请求、缓存冷热、网络／排队和服务限额。区分合法判断吞吐与正确判断吞吐，循环压力测试不增加独立题量。
- API 成本使用记录的 usage 和有日期的价格依据，单列缓存、重试及缺失用量。自托管模型记录实际 GPU 时间和计费依据；没有依据时标为未估算，不默认成本为 0。
- [参考仓库的历史结果与方法](https://github.com/JuneYaooo/jev-healthcare-lab/blob/259d0c883f4361a47be219bc779c8a290e1412ae/docs/MEDICAL_LOAD.md)仅用于设计对照。其 JEV 1.13 吞吐和成本不能直接作为我们本次模型的测量结果。

预期产物：逐题原始输出和归一化评分视图、实际模型／方法身份、完整评测日志与 checkpoint，以及按任务列出四类方法的 Markdown／JSON 比较报告。不同方法不得共享预测缓存，归一化评分不能改写原始输出。
