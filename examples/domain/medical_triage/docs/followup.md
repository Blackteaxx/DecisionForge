# 补充负结果：自然叙事优先级数据消融

主报告采用v1。第二轮确实完成了新数据构造、两次628更新训练、21个共同验证checkpoint和独立校准/新进程重载；验证选出的新增数据模型没有改善Reddit。

| 模型 | CARE135 | Synth869 | Reddit1502 |
| --- | ---: | ---: | ---: |
| v1 step200、原595校准 | 70.37% | 67.66% | 79.23% |
| control重选step628、新861校准 | 68.15% | 67.66% | 79.69% |
| hard25选step500、同861校准 | 68.89% | 70.08% | 78.16% |

hard25相对v1在Synth多对21条、Reddit少对16条；相对control在Reddit少对23条。Reddit Brier/ECE为0.3538/0.1497，v1为0.3379/0.1355，control为0.3241/0.1252。control变化同时涉及重新选模和校准，不能归因于新增训练数据。

## 方案与执行

新增仅做患者消息优先级，使用原NLM来源角色；12个开发来源不进入新增正式训练，不提供公开帖子、金标或错题。`generate --profile hard_priority` 使用 [profiles.py](../scripts/v1/profiles.py) 的平铺wire格式，无损组装公开state。四轮构造/checker接受2565条。

[hardmix.py](../scripts/v1/hardmix.py) 保护原冻结患者，构造嵌套替换集合：hard25替换594条、hard50替换1187条。所有配方仍是5024train（2650分诊、2374优先级），共享654validation、861calibration；原答案字母×优先患者位置计数保持一致。训练参数和628更新不变，样本量/更新数相同不代表FLOPs或耗时相同。

三条件各七个checkpoint共同验证，预定规则在新公开推理前选hard25/500为冠军；hard50未入选，未依据公开成绩回选。control和处理组使用逐字节相同的861条校准记录，零模型权重优化器更新；新进程4探针Choice均一致，概率最大差0.0004/0.0011≤预设0.002。

两组各执行654条原样validation、416条成对换序validation和三套完整公开测试。新增6格复用原15格，21格17542条strict-valid，传输/协议失败为0。详细指标见 [第二轮机器可读结果](../results/optimization-results.json)，API用量见 [统计](../results/data-usage-optimization.json)。

## 为什么保留为负结果

新合成优先级验证仍接近98%天花板，不能充分拉开候选；control在新叙事验证204/208，hard25为205/208。换序一致率均99.04%，不足以确认Reddit差距由大规模位置偏差引起，也不能排除Reddit特有顺序问题。

本轮同时改变叙事风格、长度与比较事实，未分别隔离因素。公开测试已在前轮分析，因此是非盲后续实验；Reddit只有一个患者连通分量，不报告独立pair显著性。自动来源/标签审查不等于临床人工裁定。GPU与教师完整费用未知。

后续应先提高独立验证材料的区分度，再决定下一次单变量实验。原训练/数据配方代码继续保留；中间checkpoint按本次清理要求删除，重新执行需新训练。主结果及其局限见 [v1 结果](../results/v1.md)，方法和消耗见 [方法与消耗](methods.md)。
