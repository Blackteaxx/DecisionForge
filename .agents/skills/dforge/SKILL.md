# DecisionForge 任务入口

把用户请求转成明确的阶段与交付终点，使用现有 DecisionForge 程序。执行前必须读取 [任务记录](../shared/task-record.md)、[执行规则](../shared/execution.md) 和 [交互与进度面板](../shared/interaction.md)。文件路径以本 skill 所在位置解析，不依赖私人 skills。

## Stage 0：需求澄清、适用性初判与路线确认

明显不属于 DecisionForge 使用请求（如仅写自由游记）时，直接说明不适用并回到相应任务处理，不建立 DecisionForge 任务或要求确认 JEV 流程。用户想用 JEV 但场景边界不清时，进入下面的澄清与适用性初判。

新任务有两个先后确认点：**先接受需求澄清方案，再完成适用性初判并确认总体路线**。没有已接受的澄清方案时，第一轮只核对必要的输入事实、展示分析范围/判据/待澄清问题和预期输出，然后停在“接受／修改／暂停”；不在同一轮直接给出已完成的适用性结论、选好数据划分或跳过某个业务阶段。用户接受后才进入第 2–4 步，不能把两个确认点合并成“我已完成初判，请确认路线”。

1. 核查仓库版本、已有任务记录和已知输入，保留已确认决定。按 [共享确认流程](../shared/interaction.md) 先展示本轮需求澄清的分析范围、判据、待澄清问题与输出，取得用户接受后开展分析；已有明确的本阶段方案授权可以沿用。
2. 明确决策目标、输入情境、候选选项或判断命题、标签/评分标准及成功标准。初判能否表达为 Choice、Noul 或有明确等级含义的 Score，是否有可核验监督/评测依据，以及当前方法能否处理输入形式和候选规模。初判不等于效果保证；支持范围以 [JEV 格式](../../../docs/zh/jev-format.md)、训练/评测选项和真实实现为准。
3. 信息不足时列出具体缺口并实际提问，相关阶段等待；纯自由创作、没有决策目标且无法明确选项/判据，或所需能力当前不支持时，说明不适用或实现缺口并建议其他路线，不强行训练。已有适用性结论的单阶段/续接任务先核对是否仍适用，不重新做整套入口访谈。
4. 适合时展示整体路线、数据条件、本次交付终点、资源与预算约束，请用户确认或修改。只在当前阶段讨论所需参数；训练量、量化、评测推理设置等留到相应阶段。**接受总体路线只确认范围和顺序，不表示已接受后续阶段方案。**
5. 初始化或更新任务 README/task.json；新任务优先用指定目录，否则在 `outputs/tasks/` 下选唯一名称。记录适用性判断及依据、路线选择、回答与待决定项。按下表或已明确的单阶段请求路由；纯研究/分析也需记录。

### 端到端任务的两个分支

| 用户的数据条件 | 默认展示的业务路线 |
| --- | --- |
| 有自有数据 | 整理并固定独立评测集 → 搜寻资料 → 整理训练数据 → 完成训练 → 评测与对比 → 性能报告与 insight |
| 没有自有数据，只有场景 | 搜寻资料 → 整理数据（独立评测集及候选训练数据）→ 用户选择是否训练 → 评测与对比 → 性能报告与 insight |

数据步骤均由 [数据 skill](../dforge-data/SKILL.md) 承接，分别展示方案并确认。自有数据先确认用途和标签，不默认全部用于训练。没有数据也要建立独立评测集，并按来源/样本分组隔离训练、验证/校准和最终测试，避免同源改写泄漏。

无数据分支在整理数据后展示训练与不训练两条路线及成本/限制，由用户实际选择；已有明确选择直接沿用。训练未选择时保持待决定，不先写入已请求训练阶段或启动训练。选择不训练时，先通过 [评测 skill](../dforge-eval/SKILL.md) 确认已有模型或免训练方案，再确认评测配置。该方案可能需要资源，不能把“不训练”称作“无成本”。

这两条是端到端默认路线，不能覆盖明确的单阶段请求。用户只评测已有模型、只找资料或只分析报告时保留其范围；已有合格数据/来源可在路线确认时明确复用或跳过，不为走流程重复生成。全流程以报告交付为终点；下一轮补数据或重训需要用户另行选择。流程图和阶段展示表见 [工作流](../../../docs/zh/agent.md)。

| 用户请求 | 阶段入口 | 终点 |
| --- | --- | --- |
| 找来源、比较数据集、给数据建议 | [数据](../dforge-data/SKILL.md) | `data/research` |
| 整理材料、生成可用 JEV 数据 | [数据](../dforge-data/SKILL.md) | `data/prepare` |
| 启动训练、别等结束 | [训练](../dforge-train/SKILL.md) | `train/launch` |
| 完成训练、跟进到模型产物 | [训练](../dforge-train/SKILL.md) | `train/complete` |
| 评测现有模型或对比模型 | [评测](../dforge-eval/SKILL.md) | `eval/launch` 或 `eval/complete`，按原请求 |
| 分析结果、给下一步建议 | [分析](../dforge-analyze/SKILL.md) | `analyze/recommend` |

例如“帮我跑一下这些数据”没有足够信息决定训练还是评测，应提供“准备数据／训练模型／评测已有模型”等相关选项；“在 train-a GPU0 用 train.yaml 启动训练后交接”已确定范围、资源和终点，先核对并展示实际配置；若用户指令明确批准了这份当前阶段配置，则沿用授权，不重复询问同一组事实。

若用户询问方法，先解释当前选择：[原生训练](../shared/training-options.md) 支持 Unsloth LoRA/full、Laya RLCD 与 OpenJev 两阶段 RLCD；LoRA 的 4-bit 加载可选，full 禁用量化；[评测](../shared/evaluation-options.md) 可用已有原生服务、对应版本化本地产物，或 Chat baseline / LLM2Jev / AnyJev L0 training-free 路线。不要把训练方法、推理 adapter 和 benchmark 混成一个菜单。

## 进度面板

明确范围后展示一张总面板，后续只在标记、流程分支、阻塞原因变化或用户询问进度时更新。步骤名称写明请求终点；未请求阶段可标 `[-]`，但不写进 task.json 的请求阶段。

```text
DecisionForge 进度
[x] 0. 需求澄清与整体路线确认
[x] 1. 整理并固定评测集
[x] 2. 搜寻资料
[x] 3. 整理训练数据
[!] 4. 完成训练（等待接受本阶段方案）
[ ] 5. 评测与比较
[ ] 6. 性能报告与 insight
```

根据实际请求改写此示例，不能复制示例的已完成状态。阶段 skill 的子步骤由你跟进，不叠加多张面板；同阶段只有 loss/步数变化时用一句进展更新。仅启动任务写“训练启动与交接”，该步骤完成时注明 run 仍 running。

## Stage 1–4：按请求执行对应阶段

已具备模型和数据时直接进入评测方案确认；只有要求训练时才训练。分析默认交付报告与建议，用户选定下一步后再调用对应阶段。用户明确要求的多个阶段按依赖顺序进入各自的方案确认；同一业务阶段的已确认配置不重复询问。

默认通过独立阶段命令完成生成、训练和评测，以保留每个业务阶段的确认停点。下游使用实际返回路径；上游暂停或失败时不继续下游。[端到端入口](../../../docs/zh/quickstart.md) 与 `scripts/run_workflow.py` 不内置用户确认门，不能因路线已确认而直接调用；其适用条件与明确自动执行授权见 [执行规则](../shared/execution.md)。

接续任务先核查资源当前状态、实际 manifest 与文件，再选择监控、已有恢复命令或交接。旧索引 running 不证明当前在运行；已启动作业不重复提交。没有建立跨会话检查能力时不能承诺会话结束后继续监管。

## Stage 5：交付前检查

- 用户要求分享、整理或提交时，已按 [自包含交付目录](../shared/delivery.md) 准备来源与脚本、benchmark 扩展、README、结果与细节文档；不提交 `outputs/`。
- 请求的阶段和执行终点已写明，所有本地交付能从任务根目录找到。
- README 与 task.json 已更新，实际运行路径、证据、外部引用和待决定项一致。
- 启动请求可 fulfilled，而 run 仍 running；完成请求须核查终态，效果达标另行判断。
- 缺少定价、资源、标签含义等关键条件时，保留已完成部分与具体方案，不猜测、不绕过检查。
- 最近一次面板、README 与实际状态一致；需要用户决定的问题已实际提出，回答已登记；配置选择和偏离示例的理由已归档。

例如“比较模型 A/B，给下一步建议”只进入评测与分析；已有兼容评测报告时先复用报告。不能因此自动准备新训练数据或重训。
