# 可分享的自包含交付目录

用户要求整理、分享或提交实验时，在版本控制可见的位置准备一个集中入口；位置沿用用户选择，否则优先使用 `examples/domain/<case>/`。`outputs/` 保存工作记录和运行产物，不作为对外阅读的必要依赖，也不加入 Git 提交。

让读者从一份 README 开始即可。可分享的数据、配置、必要的转换脚本、benchmark 扩展、方法说明和结果分别集中到 `data/`、`configs/`、`scripts/`、`benchmark_ext/`、`docs/`、`results/`，按实际需要使用这些目录，根目录不平铺执行脚本。能用仓库命令表达的步骤直接写成命令；一次性调度、环境迁移、会话统计和交付检查工具通常无需随案例保留。确实用于历史结果的专用实现单独标明版本和用途，避免成为后续任务的默认入口。

按已请求阶段准备以下内容；没有执行的阶段省略，不为凑齐目录启动新实验：

- 训练数据、来源与清洗脚本：适合随案例分享的实际冻结数据放在 `data/`，附划分、字段、数量与哈希；同时提供实际 URL/revision、许可、来源角色与标签映射、转换/隔离方法。数据不随包提供时写清获取方式。
- 测试数据与 benchmark 接入代码：冻结来源、完整数量、可复现转换、独立扩展源码及安装方式。
- README：做了什么、结果如何、正式采用的版本、复现入口和限制。
- 结果文档：实际指标与分母、方法条件、失败和覆盖、主结果与补充实验的区分。
- 细节文档：资料、生成/清洗、训练/选模/校准、评测方法、软件与模型版本、API/GPU/coding agent 的耗时和消耗。只写有证据的统计；缓存、并行时间与不同计数口径要说明，未知费用保持未知。

阅读所需文档、任务专用脚本、配置模板、扩展与小型结果摘要放在同一目录，使用内部相对链接；不能只链接被忽略的 `outputs/`、私人绝对路径或外部软链接。允许依赖仓库核心、公开数据和模型下载，但要说明安装、获取方式、固定版本与未随包提供的内容，不能把源码文档交付称为完整权重备份。生成数据有随机性时，区分重新执行方法与字节级复算原实验。

交付前检查本地链接、脚本和配置路径、来源及结果身份，确认 Git 暂存不含 `outputs/`、凭据、大模型或临时文件。保留失败和负结果摘要，不复制全部内部日志。若本轮同时获授权清理存储，先保留交付需要的来源、结果和最终版本，记录删除范围、实际释放量及对恢复的影响；本规范本身不授权删除。
