# 数据研究与准备

执行前读取 [任务记录](../shared/task-record.md)、[执行规则](../shared/execution.md)、[交互与进度面板](../shared/interaction.md)，以及 [生成文档](../../../docs/zh/data-generation.md)。本阶段止于用户要求的来源建议或可用数据交付。

## Stage 0：明确数据交付

先读取目标、材料和已确认决定；按共享规则展示当前业务阶段方案并实际等待接受，缺失关键答案与方案确认可在同轮收集（无适用工具时文本提问）。优先明确：只找来源还是准备可用数据、题型/标签及质量要求、获取/生成所用资源与已给预算。不要让用户重复解释可从数据卡、字段或已有决定中查到的信息；来源内容无法验证时明示限制。

选择生成配置时展示 `task.modes`（auto/choice/noul/score）、已有标签映射、是否从 TXT 构造问答、是否补上下文、验证留出和模型/预算。已有问题/答案只按授权保留或转换；标签歧义实际提问，等待答案再生成。已是可用 JEV 的输入可提出仅验证和归档的方案，确认后执行，不为使用本 skill 强制重新生成。

独立调用的面板步骤为：`0 明确目标与终点 → 1 来源研究/输入核查 → 2 整理与配置 → 3 生成与验证 → 4 归档交付`。研究请求将不需要的生成步骤标 `[-]`；已有来源跳过无关研究。按共享规则仅在步骤、分支、阻塞变化或用户问进度时显示，串联任务沿用总面板。

## 数据业务阶段与评测隔离

| 业务阶段 | 展示并确认 | 产物与停点 |
| --- | --- | --- |
| 整理自有评测集 | 输入用途/版本、标签、覆盖/规模、指标、划分与隔离规则 | 固定评测集、数据身份与隔离记录；完成后进入资料搜寻确认 |
| 搜寻资料 | 来源类型、检索范围、筛选标准、数量与停止条件、资源/成本 | 来源报告、证据及推荐；继续整理前确认下一方案 |
| 整理训练/场景数据 | 输入来源、结构、标注/生成方式、规模、质检、split、模型/预算 | 可用训练数据及独立评测集（若本次范围包含），失败与质量报告 |

这些是分开的业务阶段，不因都属于 `data/prepare` 就一次授权全部执行。每阶段的预检、转换、生成、验证和归档可包含在同一具体方案中；不按命令重复确认。没有 YAML 的研究或评测集整理也保存方案版本，路径见 [任务记录](../shared/task-record.md)。

端到端有数据路线先固定独立评测集，再以训练来源池搜寻/整理训练数据；不把全部自有数据直接送进训练生成。只有场景时先建立数据和评测依据，再由用户选择是否训练。候选训练材料不代表已授权训练；已选择不训练时按需要只准备评测数据，不强行制造训练集。

保留来源、record/group ID、split 和版本/哈希；在生成改写或切分之前按原始案例/文档/来源分组隔离，检查重复与同源改写，避免最终评测题目及答案进入训练、验证/校准或调参过程。共享公开知识本身不等于泄漏；要核查的是样本和派生链是否穿越划分。缺少可信标签/判据时先说明评测能力边界，不能以模型自己生成的答案证明自身准确率。

## 确定需求与来源

1. 读取用户目标、已有数据和历史决定，明确领域/能力、题型、标签含义、数量与质量要求、执行终点和指定资源。事实先检查，影响语义的缺失决定才询问；不要凭字段名猜 X/Y、零起始或一起始标签。
2. 用户给出数据时检查实际字段、样本、答案、分组、划分、来源与已知使用条件；记录输入原位置和版本。有可用输入时不强制开展无关研究。
3. 缺数据时开展面向目标的研究：分别检索现成数据集与原始材料，按能力/子任务、领域术语和必要语言扩展查询。优先实际数据卡、发布仓库、论文和发布机构文档；读取内容或样本核实相关性，不能只看摘要便声称适用。
4. 按 [研究报告模板](../shared/templates/research.md) 保存检索范围、实际链接、版本/获取时间、覆盖、标签/字段、质量局限、已知使用条件和获取方式。比较直接转换、从材料构造问答的成本与证据，给出推荐组合和缺口。来源不足时如实交付限制，不无限扩大任务。
5. `research` 请求到来源报告结束；缺工具或无法验证来源时记录未完成核查，不假装深度研究已完成。`prepare` 请求在研究交付后进入整理方案确认，展示所选来源与处理策略并等待接受；整体数据准备请求不代替本次整理方案的确认。

## 准备与生成

材料出题优先使用仓库的 TXT 评估、问答构造、题型补全和 checker；已有问答则走 JSON 输入。来源解析和格式转换可以用小脚本，模型生成和恢复尽量沿用现有流程。若特定输入结构、固定候选目录或配额无法由当前配置表达，先说明这个差别，再决定是否需要扩展；结果说明也要区分实际使用了哪些原生能力。

将本地获取的材料、转换记录和工作数据放入 `data/inputs/`、`data/prepared/`。当前生成入口支持 JSON/TXT；CSV、JSONL、PDF 等来源先用可用外部工具转换，记录方法与证据。无法转换时说明缺口。保留源问题/答案、标签映射、group 与 split，不为凑数量静默删样本、重标或编造答案。

长 TXT 分批会在输入文件同级写 `batches/`。先创建任务内的真实工作副本，核对副本与源，不能把源文件软链接进任务后直接执行。远程处理先准备任务所属远程工作目录，再登记大文件引用。具体规则见 [长 TXT 分批](../../../docs/zh/data-generation.md)。不要预报切分数量、丢失或覆盖情况；核对实际批次和 meta。

需要生成时按以下顺序执行，路径示例须换成真实任务位置；只研究或验证已有 JEV 不执行 build：

```bash
uv run dforge data inspect --config outputs/tasks/grid/data/runs/gen-001/config.yaml
uv run dforge data build --config outputs/tasks/grid/data/runs/gen-001/config.yaml
# 下面的 ACTUAL_RUN 是 build 返回的实际 run_directory，不是猜测路径。
uv run dforge data validate --input "$ACTUAL_RUN/accepted.json"
```

上述命令属于已接受的整理方案；未确认时只可进行必要的离线预检，不执行 build 或批量处理。执行前重写任务配置中的输入、映射和输出路径；YAML 相对路径以 YAML 所在目录为起点。stdout/stderr 保存到任务内，读取实际 `run_directory` 并登记。`inspect` 离线；`build` 即使字段齐全也会调用 checker，需要已指定模型服务。预算有定价前不能声称已落实；`validate` 只证明结构契约，不证明答案事实正确。

中断时先核对状态与 `.dforge/`，使用 `uv run dforge data resume --run-dir "$ACTUAL_RUN"`。按用户所需格式用现有 `export --run-dir ... --format ...` 导出；不需要导出的格式不额外生成。恢复、重导出和重新生成的语义不同，不能混用。

## 验收与交付

读取实际 `accepted.json`、`fail.json`、`meta.json` 与状态；统计接受/失败/待复核数量、题型、来源和划分。尚未形成合法候选的输入失败可能只在 meta 中，不能只看 fail 数量。用户要求的数量或质量不满足时明确缺口；保存 checker 和来源记录。

报告、实际配置、结果与失败入口写进 README/task.json；区分 research/prepare、请求状态、run 状态和效果判断。研究报告本身也必须落入任务目录；后续训练与评测只在用户请求时进入各自的方案确认；无数据分支先确认是否训练。

常见错误：在原 TXT 旁留下批次；复制配置却保留旧相对路径；忽略实际版本目录；把结构验证或 checker 通过等同于事实完全正确；为完成任务猜标签或取消预算。
