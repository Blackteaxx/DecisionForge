# 结果分析与下一步建议

执行前读取 [任务记录](../shared/task-record.md)、[执行规则](../shared/execution.md)、[交互与进度面板](../shared/interaction.md) 与 [分析模板](../shared/templates/analysis.md)。本阶段交付报告和可执行建议，默认不进入新一轮实验。

## Stage 0：明确分析问题与证据范围

先读用户问题和必要的证据目录，展示本次证据范围、比较对象与指标/分母、分析维度和重点业务问题、离线方法、报告形式与输出、资源/成本及限制。即使路径和指标都已知，也要按共享规则实际等待用户接受或修改分析方案后再做完整分析；已有同一具体分析方案的接受记录可沿用。**用户在初始请求中说“只分析”“给报告”或指定 `analyze/recommend`，只确认分析阶段和交付终点，不确认 agent 后续拟定的分析策略；不得据此直接写报告、把阶段标为 `completed` 或把请求标为 `fulfilled`。** 没有已确认的同一具体方案时，第一轮必须展示方案并停在“接受／修改／暂停”；只有用户在看到该方案后明确接受（例如“接受上面的分析方案，按此执行”），才能进入完整证据收集、统计、报告撰写和归档。用户修改方案后重新展示并等待接受。工具不可用时文本提问。用户已说“只分析并给建议”就保留这一范围，不重新询问是否要新实验；证据缺失时在方案中说明可交付的边界，不为了补齐证据自行启动推理。

本 skill 的收集证据、统计、判断、撰写和归档是一个报告分析业务阶段的内部步骤，不逐项再设确认门。

独立调用的面板步骤为：`0 明确分析范围 → 1 收集与核对证据 → 2 判断问题与原因 → 3 排序建议 → 4 报告交付`。只在步骤、阻塞原因变化或用户询问时显示，串联任务沿用总面板。分析交付可以完成，而尚未验证的效果仍为 unknown；建议待选择不等于本轮报告未交付。

## 收集与核对证据

1. 读取用户目标、请求范围、已有记录和实际数据/训练/评测报告。用户未指定目录时在 `outputs/tasks/` 下创建唯一任务目录；仅分析也需 README、task.json 和 `analysis/<report-id>/`。
2. 核对实际来源、数据版本与划分、模型/配置身份、运行状态、指标定义与分母、样本覆盖和失败项。没有全部阶段产物时分析证据能支持的范围，说明缺失对判断的影响；用户提供数值与自己读取结果要区分。
3. 先验证比较条件。参考 [评测规则](../dforge-eval/SKILL.md) 及 [指标契约](../../../docs/zh/evaluation.md)，对不同数据、split 或评分口径分别报告，不能因数值更高就推断模型改善。
4. 可读取已有样本/预测、计算描述性统计、检查配置和损失曲线、离线重评分。新增分析文件写入任务目录；若重评分需写报告，先准备任务所属的完整必要评测记录，保护原始外部运行。

## 判断问题与原因

逐项给出观测、证据位置、影响范围和可能解释。只有有区分力的证据或已完成的验证支持时才把原因列为已确认；否则标为待验证假设，并说明如何支持或否定。

| 观察 | 可支持的判断 | 仍需要的证据 |
| --- | --- | --- |
| loss 下降、test accuracy 低 | 当前优化目标在改善，测试表现有限 | 指标/分母、验证曲线、分布、错误样本；不能直接认定标签噪声 |
| 某类错误集中 | 该类在当前样本中存在问题 | 样本量、标签审计、覆盖与对照；不能直接认定模型能力缺失 |
| 评测含大量失败或 partial | 当前报告覆盖不完整 | 失败原因、实际模型与有效分母；不能把失败全算作能力下降 |

例如只有 loss 下降和准确率 0.55，即使同事催促“立刻重标重训”，也先给证据不足的判断和小范围核查建议。截止时间不是原因证据或改动数据的授权。

## 建议与交付

按信息价值、影响与已知资源条件排序，列出具体动作、要验证的假设、需要的材料/资源、验证方法和预期观察。优先能区分原因的核查或单变量实验；不把未知收益、成本和准确率提升写成确定数字。

新增数据生成、改标签/划分、训练、模型推理评测、改评测口径或源码变更都列为下一步方案，等待用户选择。离线分析不等于允许启动新推理；用户已明确选定的后续行动进入相应阶段的方案确认；只有同一具体方案已被接受时才沿用确认。

报告应包含实际性能指标与分母、对照结果（若有）、错误案例/失败模式、适用边界和改进建议。未训练路线报告已有模型或免训练方案的表现；没有训练前后同口径对照，不能声称训练带来提升。缺少逐样本证据时明确不能完成错误案例分析，不编造案例。

保存报告、比较依据和离线计算到 `analysis/<report-id>/`，归档可取得的小型证据，外部数据/大模型登记引用。更新 README/task.json 的报告入口、效果判断和待选择建议。完成有界分析后可交付 `analyze/recommend`，但不把尚未验证的效果目标写成 met。

常见错误：不建任务目录只在对话里分析；把相关性或 loss 走势当作原因；忽略失败分母；为了验证猜测自行调用模型；给建议后自动开始下一轮。
